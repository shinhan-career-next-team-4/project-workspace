## 왜 개정했나

D-085로 FR-INP-08('지금 하고 있는 저축' 토글)이 Must로 돌아왔다. 사용자가 입력 화면에서 적금 : ETF 비중을 정하는데, v3 계약은 `savingsRatioPct`를 "요청에 없는 것"으로 두고 서버가 현재 버전 값을 복사하므로(R-9) 화면이 정한 비중을 보낼 길이 없었다. 그래서 `PUT /api/plan` 요청 필드로 올린다.

**재검토에서 합의로 처리한 것** (사람이 보고 이견이 있으면 말해 주면 된다)

- **쟁점 Z-1(가장 큰 것)**: 1차에서 제공자는 "`null` → `NULL` 저장(= 5:5)"을, 소비자는 "`null` → 비중 유지 + 토글을 끌 때 `50` 전송"을 들고 부딪혔다. 기획이 둘을 합쳐 **OFF는 항상 `null`, 복원 ON·칸 비움은 받은 값을 되보내기**로 냈고, 재검토에서 제공자 "수용, 서버 추가 코드 0줄", 소비자 "A 수용, ③안 철회"로 닫혔다. 이로써 ① D-085 "끄면 5:5"가 참이 되고, ② 기본 비중 수치 `50`이 프론트에 복제되지 않고(CP-02), ③ 토글을 안 건드린 일반 수정이 대화로 정한 비중을 지우지 않는다.
- **함께 확인된 사실**: `savings_ratio_pct`의 `50`과 `NULL`은 계산 엔진·planContext·대안/비교/대화 재계산·`display`·`assumptions`에서 **모두 같게 취급된다**(전부 `ConditionResolver.resolveRatio`가 해석한 int만 쓴다). 차이는 `PlanView`가 원본을 그대로 내보내는 것 하나뿐이고, 그 차이는 토글 복원과 가정 보기 표시 조건에만 쓰인다.
- **남은 구멍 하나와 그 처리**: `loadPlan()`이 확정되기 전에 저장하면 "복원 ON·칸 비움"과 "OFF"를 구분할 수 없어 서버 비중이 지워진다 → **확정 전 저장 버튼 비활성**으로 막는다(소비자 재검토 1).
- **동시 수정**: 다른 탭이 먼저 비중을 바꾼 뒤 옛 값을 되보내는 경우는 `expectedRevision` 검사와 조건부 UPDATE가 **이미 409로 막는다**. 서버에 "되보낸 값인지" 확인을 넣지 않는다(넣으면 버린 복사 로직이 되살아난다).
- **`rules.yml`은 건드리지 않는다**: 초안이 "추가"라고 쓴 것은 구조 오독이었다. 계약이 "추가"로 남아 있으면 구현자가 중복 키를 넣거나 `INPUT_EDIT`에 `fields:` 목록을 만들어 `all-fields: true`를 깨뜨린다.
- **차액 문구에서 금액을 뺀 이유**: 금액을 쓰면 화면이 "월 저축 가능 금액 − 납입액 합계"를 계산해야 하고(NFR-INT-01), 납입액은 저장하지 않으므로(D-043) 새로고침·재로그인 뒤에는 합계를 알 수 없다. 서버는 납입액을 받지 않아 대신 만들어 줄 수도 없다. 고정 문장도 CF-08 ②의 "그 사실을 명시한다"를 만족한다.
- **문구표 담당**: 문구표 초기 키 Issue #18은 CLOSED이므로 키 7개는 **#127이 더한다**(`copy/copy.ko.yml`을 #127 paths에 그대로 둔다).

## 사람이 정할 쟁점

**없다.** 초안의 쟁점 3개는 모두 닫혔다.

| 초안 쟁점 | 결과 |
|---|---|
| (a) `STALE_COMPARISON`을 B팀 화면에서 어떻게 안내할까 | **닫힘** — 추가 작업 없음. 문구 문장만 교체(Z-11) |
| (b) 기본 비중 값이 계약에 없어 "토글을 끄면 5:5"가 거짓이 되는 구멍 | **닫힘** — `null` = `NULL` 저장(= 기본 비중) + 되보내기(Z-1·Z-2 → D-086). 명시적 기본값 `50`을 계약에 넣는 안은 CP-02 때문에 채택하지 않았다 |
| (c) 입력 수정 복원 때 토글 상태 | **닫힘** — (A)안(Z-12 → D-089) |

사람이 다시 볼 만한 곳은 **D-086~D-089의 상태가 '임시'**라는 점뿐이다. 특히 D-086의 부작용 하나를 알아 두면 좋다: **사용자가 토글을 직접 끄고 저장하면, 대화·대안으로 적용했던 비중이 기본 비중으로 돌아간다.** D-085의 "나중 변경이 이긴다"에 부합하고 토글 아래 안내로 예고하지만, 다르게 하고 싶으면 말해 주면 된다.
