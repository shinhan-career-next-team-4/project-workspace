# GOAL-AGENT-SRS: 목표 기반 개인 자산관리 AI Agent 요구사항정의서

> 3주 해커톤 MVP 범위. 기획 에이전트들은 이 파일을 기준으로 작업합니다.

## 읽는 법
- **ID 체계**: `CP`(공통 원칙), `FR-<영역>`(기능), `NFR-<영역>`(비기능). 영역: AI, ALT(대안), AUTH, CMP(비교), DATA, INP(입력), PLAN(내 계획), RES(결과)
- **우선순위**: Must / Should / Won't. Must = 이번 해커톤에서 반드시 구현, Should = 여력이 있으면 구현(2주차 말 진행률을 보고 되살림), Won't = 이번 해커톤에서 구현하지 않음(SRS에는 유지). 2026-11-16 D-045로 Must 48 / Should 18 / Won't 2로 조정했다.
- **`[해커톤 범위 밖]`**: 설명 문장이나 수용 기준 앞에 이 표시가 있으면 SRS와 결정(D-번호)에는 유지하지만 이번 해커톤에서는 구현하지 않는 분기다(D-045). 대상 분기 4개: 월 저축액 모름, 기한 없음(목표 기간 미입력), 오래된 계획 질문, 과거 데이터 버전 보관. 해커톤 데모에서는 목표 기간과 월 저축액을 필수로 받는다(D-045). 비고의 "해커톤 범위 밖: ... (D-045)"는 행은 Must이지만 그 분기는 뺀다는 뜻이다.
- **담당**: A팀(계산 엔진·입력·결과·계획 저장·인증·데이터) / B팀(조건 탐색: 대안·비교·AI 대화·설명·RAG, D-046) / 공통. 애매한 행은 주 담당을 적고 비고에 협업 상대를 적었다. B팀은 계산을 A팀 계산 엔진 호출로 하고, 사용자가 적용을 요청하면 A팀의 확인·저장 흐름(FR-PLAN)으로 넘긴다(D-046).
- **상태**: 확정 / 부분확정 (부분확정은 `출처`의 TBD·CF 항목 중 미결·부분결정이 남아 있다는 뜻. 2026-11-16 기준 open-questions.md의 Q-xxx는 모두 결정됨)
- **출처**: `TBD-xx`, `CF-xx`는 Notion에서 관리하던 미결·결정 항목 번호입니다. 원문은 `docs/notion-decisions.md`에 있습니다. `D-xxx`는 이 repo에서 기록한 결정(docs/decisions.md), `Q-xxx`는 이 repo의 질문(docs/open-questions.md)입니다.
- **(임시: D-xxx)**: 비고에 이 표시가 있으면 그 D-번호가 decisions.md에서 상태 '임시'(Claude 판단, 진혁 위임)인 결정입니다. SRS에는 확정 결정과 같게 반영했지만 개발 중 바뀔 수 있습니다.

## 수용 기준

`[해커톤 범위 밖]`이 붙은 수용 기준은 SRS와 결정에는 유지하지만 이번 해커톤에서는 구현·테스트하지 않는다(D-045).

### CP-02 입력 허용 범위
- 정상(D-033): Given 대화로 조건을 바꾸는 사용자 / When 허용 범위 안의 값을 말하면 / Then Spring 계산 엔진의 검증을 통과해 대화창에 비교 결과가 뜬다.
- 예외(D-033): Given 대화로 받은 값(기간 포함)이 허용 범위를 벗어난 경우 / When AI 서버가 계산 엔진의 검증 오류를 받으면 / Then 범위를 알려주고 값을 다시 묻고, 비교 결과는 뜨지 않으며 내 계획과 결과 화면은 그대로다.
- [해커톤 범위 밖] 예외(D-026): Given 월 저축액 0원이고 목표 기한을 정하지 않은 입력 / When 결과 보기를 누르면 / Then 입력 검증 오류로 결과 화면으로 넘어가지 않는다.
- 정상(만원 소수 입력, 근거 계약 C12a-5-6): Given 월 저축액 입력칸 / When 사용자가 만원 단위로 `34.5`를 입력하고 저장하면 / Then 서버에는 345,000원으로 전달되고 입력 검증을 통과한다(`1.1` → 11,000원처럼 부동소수 오차가 없다).
- 예외(만원 소수 입력): Given 금액 입력칸 / When 소수 다섯째 자리 이상(`12.34567`)이나 숫자 형식이 아닌 값을 입력하면 / Then 입력 화면이 막고 형식 오류 안내를 보여주며 서버로 보내지 않는다.
- 예외(D-074): Given 직접 입력 목표명이 101자 / When 결과 보기를 누르면 / Then 입력 검증 오류(최소 1·최대 100자 안내)로 결과 화면으로 넘어가지 않고, 100자는 통과한다.
- 예외: Given 월 저축액이 범위 밖이고 목표 기간도 비어 있는 입력 / When 결과 보기를 누르면 / Then 두 입력칸 모두에 안내가 한 번에 보인다.
- 예외(D-080): Given 월 저축액 입력칸에 `long` 최댓값(9,223,372,036,854,775,807원)을 넘는 만원 값(예: `1000000000000000`)을 입력한 사용자 / When 결과 보기를 누르면 / Then 프론트가 변환 결과를 `Number`로 바꾸지 않고 JSON 숫자 그대로 보내고, 서버가 `OUT_OF_RANGE`(같은 `min`·`max`)로 막아 저장되지 않으며 기존 내 계획은 그대로다.
- 예외(D-080, Q-070 정정): Given 정수 금액 필드(예: `monthlyAmount`)에 JSON 숫자 `300000.5` / 문자열이 담긴 요청 / When 서버가 받으면 / Then 각각 422 `NOT_INTEGER` / 400 `MALFORMED_REQUEST`로 돌려주며 저장하지 않는다(`OUT_OF_RANGE`는 `long` 범위 밖 정수에만 쓴다).
- 정상(D-081): Given `CUSTOM` 목표 종류와 앞뒤에 공백이 붙은 목표명(`"  내 집 마련  "`) / When 서버가 저장하면 / Then 앞뒤 공백을 뺀 `"내 집 마련"`이 저장된다.
- 예외(D-081): Given `CUSTOM` 목표 종류에 목표명이 빈 값이거나 공백뿐인 요청 / When 서버가 검증하면 / Then `REQUIRED`로 막는다. 목표명이 UTF-16 기준 101자이면(이모지 같은 보충 문자는 2자로 셈) `OUT_OF_RANGE`(최소 1·최대 100)로 막고, 100자는 통과한다. 이 기준은 FR-INP-02 구현 전까지 API 테스트로 확인한다.

### CP-04 금액·비율 표시

- 예외(W-11, D-066): Given AI 설명이 실패했거나 아직 도착하지 않은 대화창 / When 대화창을 보면 / Then 위 안내와 D-066 상시 고지 한 줄은 모델 출력과 무관하게 둘 다 보인다.

### FR-AI-05 설명 다시 요청
- 예외(D-063): Given 보유 자산이 목표 금액 이상인 초과 계획 / When 결과 화면과 대화창을 보면 / Then '설명 다시 요청' 버튼이 보이지 않는다.
- 정상(D-072): Given 초과 계획이라 버튼이 숨겨진 상태 / When 계획 `revision`이 바뀌어 초과가 풀리면 / Then '설명 다시 요청' 버튼이 다시 보인다.

### FR-AI-08 질문 예시 버튼
- 정상(D-064): Given 질문 예시 버튼이 보이는 대화창 / When 조건 변경 예시 버튼("월 저축액을 바꿔 보고 싶어요" 등)을 누르면 / Then 계산하지 않고 `CLARIFY`로 바꿀 값을 절대값으로 되묻는다.
- 예외(D-064): Given 질문 예시 버튼 목록 / When 문구를 보면 / Then "10만원 늘리면" 같은 변화량 표현은 없다.
- (D-073) 예시 버튼 → `CLARIFY` 동작은 자동 테스트가 아니라 수동 평가로 확인한다.
- 정상(W-21; 와이어프레임 반영 2026-11-20, 출처 `docs/design/wireframes/03-result.md`): Given 결과 화면의 대화창 / When 입력창이 비어 있으면 / Then 안내 문구 '조건을 바꿔 물어보세요 (예: 월 80만 원이면요?)'와 '전송' 버튼이 보이고, 예시 목록 머리글은 '질문 예시'이다.
- 예외(M-06, W-20, D-064): Given 질문 예시 버튼 목록 / When 문구를 보면 / Then '기한을 1년 늘리면요?' 같은 변화량 표현은 없다(와이어프레임 원문 4개 문구는 D-064에 맞게 바꾼다. 절대값 질문형으로 바꾸려면 Q-096 결정이 먼저다).

### FR-AI-09 범위 밖 질문 안내
- 예외(D-067): Given 계산 결과의 세율 설명 밖인 세금 질문(예: "ISA 세제 혜택이 뭐야?", "내 세금 계산해 줘", "절세하는 법 알려줘") / When 사용자가 물으면 / Then 계산하지 않고 `OUT_OF_SCOPE`로, 문구표 `outOfScope.tax` 고정 문장(다루지 않는다는 범위 밖 안내와 금융기관·세무 전문가 확인 안내 포함)으로 답한다(D-073).

### FR-RES-06 가정 보기
- 정상(D-067): Given 세율이 15.4%인 계획 / When 사용자가 가정 보기를 펼치면 / Then 세율 `15.4%`와 함께 문구표 `tax.note` 단서 문장이 보인다.
- 정상(W-18, N-09; 와이어프레임 반영 2026-11-20, 출처 `docs/design/wireframes/03-result.md`): Given 결과 화면의 접힌 가정 보기 / When 줄을 보면 / Then '가정 보기 ▾ 적금 금리 · 지수 · 구간 기준 · 세율 · 반영하지 않은 항목'과 '펼치기'가 보이고, 펼치면 데이터 기준월(D-038)과 '환율 변동은 반영하지 않았어요'(D-027)도 함께 보인다.
- 예외(W-18): Given 같은 가정 보기 / When 항목을 보면 / Then '총보수' 항목은 보이지 않는다(서버 값·문구가 없다) ⟵ Q-094 결정 대기.

### FR-RES-07 면책 문구 상시 표시
- 정상(D-066): Given 대화창이 열려 있는 로그인 사용자 / When 대화창을 보면 / Then 메시지 유무와 상관없이 과거 수익률 고지와 "AI 설명은 참고용이며 계산 결과가 기준이에요" 한 줄이 항상 보인다.
- 예외(D-066): Given AI 설명이 실패했거나 초과 계획이라 AI 설명이 오지 않은 대화창 / When 대화창을 보면 / Then 위 고지 한 줄은 모델 출력과 무관하게 그대로 보인다.
- 정상(W-19; 와이어프레임 반영 2026-11-20, 출처 `docs/design/wireframes/03-result.md`): Given 결과 화면 / When 맨 아래를 보면 / Then 면책 문구 "본 결과는 입력하신 조건과 과거 데이터를 바탕으로 한 모의 계산이며, 실제 수령액이나 수익을 보장하지 않습니다. 특정 금융상품의 가입을 권유하지 않으며, 환율 변동은 반영하지 않았습니다. 투자 결정은 본인의 판단과 책임하에 이루어져야 합니다."가 문구표 `disclaimer`에서 읽혀 보인다.
- 예외(W-19, D-066): Given AI 설명이 실패했거나 초과 안내(FR-RES-01)가 보이는 결과 화면 / When 맨 아래를 보면 / Then 같은 면책 문구가 그대로 보인다.

### FR-INP-01 목표 종류 선택
- 정상(D-075): Given 입력 화면의 목표 종류 목록 / When 목록을 열면 / Then HOUSE, CAR, WEDDING, EDUCATION, TRAVEL, EMERGENCY_FUND 6개가 이 순서로 문구표 표시명과 함께 보이고, `CUSTOM`은 FR-INP-02를 구현하지 않는 동안 보이지 않는다.
- 예외(D-075): Given 서버가 문구표에 표시명이 없는 목표 종류 코드(예: 새로 추가된 `PET`)를 돌려준 경우 / When 조건 바나 입력 화면에 목표명을 표시하면 / Then 화면이 깨지지 않고 코드 문자열(`PET`)이 그대로 보인다.

### FR-INP-02 목표 직접 입력
- 정상(D-074): Given `CUSTOM`을 선택한 사용자 / When 목표명을 공백 포함 앞뒤를 빼고 1~100자로 입력하면 / Then 검증을 통과해 저장된다.
- 예외(D-074, D-081): Given `CUSTOM`을 선택하고 목표명이 비어 있거나 공백뿐이거나 101자인 입력 / When 결과 보기를 누르면 / Then 입력 검증 오류(빈 값·공백뿐은 `REQUIRED`, 101자는 `OUT_OF_RANGE`)로 결과 화면으로 넘어가지 않는다.
- 예외(D-081): Given `HOUSE` 등 `CUSTOM`이 아닌 종류를 고르고 목표명이 함께 넘어온 입력(101자여도) / When 저장하면 / Then 목표명은 검증하지 않고 `null`로 저장된다.
- (D-081) 이 행은 Should라 구현 전까지 위 서버 규칙은 CP-02 수용 기준의 API 테스트로 확인한다.

### FR-INP-05 보유 자산 입력
- 정상(D-082): Given 계획이 없는 사용자의 빈 입력 화면 / When 화면이 뜨면 / Then 보유 자산 칸에 `0`이 채워져 있고 그대로 저장하면 0원이 허용 값으로 저장된다.
- 예외(D-082): Given 보유 자산 칸의 `0`을 지우고 비운 입력 / When 결과 보기를 누르면 / Then `REQUIRED` 입력 검증 오류로 해당 칸에 안내가 보이고 결과 화면으로 넘어가지 않는다.

### FR-AUTH-01 로그인
- 정상(D-078): Given 한 브라우저에서 탭 A와 탭 B가 열려 있고 탭 B는 다른 계정으로 로그인한 상태 / When 탭 A에서 로그인에 성공하면 / Then 탭 B가 공유 store를 비우고 `loadPlan()`부터 다시 시작해 탭 A 계정의 계획(없으면 빈 입력 화면)이 보인다.
- 예외(D-078): Given 위 상황의 탭 B에 이전 계정의 입력 중인 값이 남아 있는 경우 / When 탭 B가 로그인 알림을 받으면 / Then 이전 계정의 입력값과 `revision`이 남지 않아 저장해도 다른 계정의 계획을 덮어쓰지 않는다.

### FR-INP-11 입력값 유지(입력 수정)
- 정상(근거 계약 C12a-5-6): Given 대화 적용으로 월 저축액이 345,000원이 된 내 계획 / When 결과 화면에서 입력 화면으로 돌아가면 / Then 월 저축액 칸에 `34.5`(만원)가 보이고 반올림·내림 없이 채워진다.

- 예외(D-076): Given 서명 키가 고정된 설정값인 서버 / When 서버를 재시작하면 / Then 재시작 전에 발급된 만료 전 쿠키로 계속 요청할 수 있다.
- 예외(D-052): Given 만료된 토큰 / When 요청을 보내면 / Then 요청을 처리하지 않고 로그인 화면으로 보낸다.
- 정상(D-079): Given 로컬 기본 설정(허용 출처 목록이 빈 값) / When Vite 프록시를 거쳐 같은 출처로 로그인·계획 조회를 하면 / Then CORS 설정 없이 정상 동작한다.
- 예외(D-079): Given 프론트와 API 주소가 다른 원격 배포 설정에서 허용 출처 목록이 채워진 서버 / When 목록에 없는 출처에서 요청이 오면 / Then 브라우저 CORS 검사에서 막히고, 목록에 있는 출처는 코드 변경 없이 통과한다.
